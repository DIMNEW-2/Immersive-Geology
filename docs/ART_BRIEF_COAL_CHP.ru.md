# Арт-бриф: модели и текстуры цепочки «угольная ТЭЦ»

> Дополнение к [`MULTIBLOCK_MODELS.ru.md`](MULTIBLOCK_MODELS.ru.md) (механика конвейера: шаблон → OBJ →
> текстуры → регистрация → датаген) и [`COAL_CHP_CHAIN.md`](COAL_CHP_CHAIN.md) (логика, порты, баланс).
> Этот документ — производственный: **что именно** смоделировать и нарисовать по каждой машине,
> с каких референсов, чем и как экспортировать, куда положить и как проверить.
> Английская версия: [`ART_BRIEF_COAL_CHP.md`](ART_BRIEF_COAL_CHP.md).

Состояние на сегодня: все пять машин работают на **процедурных заглушках** (собраны
`tools/tpp/models.py`), текстуры — технические атласы 128×128. Задача арта — заменить их
настоящими моделями и текстурами, не трогая логику и шаблон структуры.

| `district_heater` | `.../obj/district_heater/...obj` + `.mtl` | `default.png` | как у конденсатора |

Полные пути:

```
src/main/resources/assets/immersivegeology/models/block/multiblock/obj/<mb>/<mb>.obj      <- модель
src/main/resources/assets/immersivegeology/models/block/multiblock/obj/<mb>/<mb>.mtl      <- материалы
src/main/resources/assets/immersivegeology/textures/block/multiblock/<mb>/default.png     <- атлас
src/main/resources/assets/immersivegeology/textures/block/multiblock/<mb>/default_active.png   <- только coal_boiler
```

Опционально (уровень «потом»):

| Ассет | Зачем | Где |
|---|---|---|
| `display_<mb>.obj` | упрощённая модель для руки/GUI, если полная тяжела или нечитаема | тот же каталог `obj/<mb>/` + строка в `IGComplexItemModelProvider.generateCoalChpModel(...)` (прецеденты: `ballmill/display_ballmill.obj`, `steam_turbine/steam_turbine_item.obj`) |
| скины `<skin>.png` | варианты окраски как у `steam_turbine` (green/industrial/steampunk) | **требует кода**: enum скинов, `IMultiSkinBlock`, skinnable-регистрация, `generateMultiskinMultiblock` — см. §7 |
| `.png.mcmeta` | анимация (мигание топки, лента) | рядом с текстурой; прецеденты `foundry/conveyor.png.mcmeta`, `block/fluid/default_still.png.mcmeta`; см. §4.4 |

**Не создается и не правится руками:** всё в `src/generated/resources/` (blockstate, `*_split.json`,
`*_mirrored_split.json`, item-модели, loot, рецепты) — это продукт датагена (`./gradlew runData`)
или его офлайн-зеркала `tools/tpp/datagen_mirror.py`. Файлы `.nbt` структуры тоже не трогаются:
арт подстраивается под форму, а не наоборот.

### 1.3 Структурные референсы (обязательные)

Модель надевается «скорлупой» на реальную раскладку блоков структуры — игрок сначала видит
её из блоков, потом она собирается в мультиблок, и силуэт не должен противоречить раскладке.
Раскладки целиком — в `tools/tpp/structures.py` (ASCII-слои) и в `.nbt` шаблонах. Легенда букв:

```
C srconcrete   R пром. шамот   B шамот   S нерж. лист   M hastelloy лист   N нерж. блок
A hastelloy блок  X быстрорез блок  Y быстрорез лист  T/H инженерные блоки W/H-сплавы
L/E/Q IE light/heavy/rs engineering   P труба   G генератор   D радиатор   1/2/3 катушки
K стальный лист   O стальной блок   U бетон   V бет. плитка   F леса   Z стальная плита   W воронка
```

Координаты ниже — **model space** = координаты блока структуры минус master-блок

| Машина | Размер | Bounding box модели (min..max) | Треугольников сейчас (заглушка) |

| `coal_boiler` | 5×7×5 | (−2,−1,−2)..(3,6,3) | ~2064 |
| `electrostatic_precipitator` | 5×9×4 | (−2,0,−2)..(3,9,2) | ~1680 |

### 2.1 `coal_boiler` — котлоагрегат (пылеугольный котёл)

Слои (y=0 низ): фундамент и золовой бункер → топка с поясом горелок → экраны-водостены →
пароперегреватель → барабан с экономайзером → конвективная шахта с дымососом → крыша с
бункером угля и газоходом.

Что должно читаться в модели:

- **y0**: бетонный цоколь, по центру снизу воронка золового бункера с шибером
  (порт выгрузки золы — низ, клетка (2,0,5)); по углам — кожухи вентиляторов наддува.
- **y1 (топка)**: шамотные стены; на **front (−Z)** пояс из 4 горелок с гляделками — это же
  окно активного свечения; на **back (+Z)** — дверь/щит (тут trigger формирования).
- **y2–y3**: панельные водостены, вертикальные трубные пучки по бокам; на front y3 —
  **фланец острого пара** (порт (2,3,0)).
- **y4**: горизонтальный барабан (цилиндр вдоль X) с люком и водоуказателем, змеевики
  экономайзера; на back — **вход питательной воды** (порт (2,4,4)).
- **y5**: конвективный газоход, круглый корпус дымососа с боку.
- **y6 (крыша)**: спереди — **газоход с фланцем** (порт (2,6,0)), по центру — бункер
  пылеугля с воронкой (**вход топлива сверху**, порт (2,6,2)), сзади — шкаф управления
  (redstone-порт (2,6,4)). Энергопорт (4,1,4) — оформить как клеммную коробку справа-сзади.
- Активная текстура: свечение гляделок горелок и окна топки (янтарь `#ffa100/#ffbf00`),
  суммарно ≤2 % пикселей атласа, UV те же.

### 2.2 `electrostatic_precipitator` — электрофильтр с трубой

- **y0**: бетонный фундамент и 4 пирамидальных бункера золы с затворами (выгрузка (2,0,4)).
- **y1**: корпус; на front — **входной газоход грязных газов** с фланцем (порт (2,1,0));
  на back — клеммная коробка (энергопорт (2,1,3)).
- **y2…y4**: три секции электродов: панельный корпус с вертикальными рёбрами жёсткости,
  сбоку коробки изоляторов и механизм встряхивания (кулачковый привод).
- **y5**: выходной пленум, трансформаторные выпрямители (ящики с радиаторами) на боку/крыше.
- **y6**: крыша; **y7–y8**: дымовая труба 1×1 по центру с раструбом/зонтиком — из неё
  визуально выходит очищенный газ.
- Характер поверхности: крупнолистовая обшивка с болтовыми стыками, ржавые потёки от верхних
  кромок (см. референс трубы).

### 2.3 `steam_condenser` — поверхностный конденсатор

- **y0**: hotwell (короб снизу по центру) и водокамеры по обоим концам вдоль X: круглые
  болтовые крышки; справа вход циркуляционной воды (0,1,1), слева выход (3,1,1).
- **y1**: горизонтальный цилиндрический корпус вдоль X с трубными решётками; сбоку сзади —
  конденсатный насос (скид с мотором); на back — панель (энергопорт (1,1,3));
  снизу сзади — патрубок конденсата (1,0,3).
- **y2**: прямоугольный паровпускной патрубок с фланцем сверху-спереди (порт (1,2,0) FRONT)
  и маленький эжектор воздуха (цилиндр с конусом) рядом.

### 2.4 `cooling_tower` — градирня (зеркальная)

- **y0**: водосборный бассейн — бетонное кольцо, внутри тёмная вода; выход охлаждённой воды
  снизу-сзади (3,0,6).
- **y1**: жалюзи (louvers) по периметру — наклонные планки с просветами (просветы = alpha);
  сторона +Z — вход обслуживания (trigger (3,1,6)).
- **y2–y3**: ороситель и водоуловитель — тонкие пакеты пластин, видимые сквозь жалюзи.
- **y4…y8**: гиперболоидная оболочка: широкая у y4–5, «горло» y6–7, раструб на y8; бетон с
  вертикальными швами опалубки и потёками; сверху-сзади входит труба горячей воды (3,4,6),
  справа подпитка (0,0,3).
- Зеркальность: лоадер сам отзеркалит модель по свойству `mirrored`; асимметричные детали
  (лестницы, трубы) дублировать не надо — второй OBJ **не нужен**.

### 2.5 `district_heater` — сетевой подогреватель (ПСВ)

- **y0**: рама и скид сетевого насоса; trigger формирования — центр низа (1,0,1).
- **y1–y2**: вертикальный корпус в изоляционной обшивке с бандажными кольцами; патрубки с
  фланцами: обратная сетевая вода справа (0,1,1), подача горячей слева (2,1,1); на back y2 —
  шкаф управления (панель с приборами).
- **y3**: паровая камера: купол/плоская крышка с фланцем входа пара сверху-спереди
  (порт (1,3,0)); снизу-сзади патрубок конденсата (1,0,2); энергопорт (0,0,1) — клеммник на раме.

## 3. Создание модели

### 3.1 Инструменты

- **Blender 4.x — основной путь**: все существующие модели репозитория экспортированы из него
  (заголовки `# Blender 4.2.3 LTS` в `.obj`/`.mtl`), значит его экспортные настройки уже
  совместимы с конвейером.
- **Blockbench — допустим**, но после экспорта обязательно проверьте ориентацию V тестовой
  текстурой с надписью (см. §3.4): UV-пространство Blockbench «minecraft-овское» (y вниз),
  а конвейер ждёт blender-овское + `flip_v: true`.
- Текстуры: Aseprite / Pixelorama / GIMP / Photoshop — любой редактор с пиксельной сеткой и
  экспортом PNG 8 бит RGBA.

### 3.2 Сцена и система координат

1. 1 единица Blender = 1 блок; включите сетку с шагом 1.
2. Импортируйте текущий OBJ-заглушку (`File > Import > Wavefront`) как «скелет» и каркас
   границ: его bbox уже равен таблице из §2. Моделируйте поверх, в конце скелет удалите.
3. Оси: **front машины = −Z**, trigger/игрок = **+Z**, Y вверх, начало координат = master-блок
   структуры (т.е. клетка master занимает куб (0,0,0)..(1,1,1)).
4. Не применяйте отрицательный масштаб; применяйте scale/rotation перед экспортом
   (`Ctrl+A > All Transforms`).

### 3.3 Геометрия и материалы

- Грани: quad/tri; n-gon экспортёр сам триангулирует, но лучше держать quad.
- Убирайте грани, которые заведомо никогда не видны (внутри закрытой скорлупы), но не
  «дырявьте» скорлупу: split-рендер рисует модель по кускам на блок, внутренние стенки
  спасают от просветов на стыках частей.
- Coplanar-поверхности (накладки, таблички) разводите на ≥1/256 блока, иначе z-fighting.
- **Ровно один материал на машину**, имя = registry-имени машины (`coal_boiler`,
  `cooling_tower`, …). Никаких `Material.001`: после экспорта проверьте `usemtl` в OBJ.
- MTL после экспорта правится руками (Blender пишет абсолютные пути — в старых файлах
  репозитория до сих пор валяется `C:/Users/...`, не повторяйте):
  - `coal_boiler`: `map_Kd #coal_boiler` (решётка = «текстуру подставит датаген»);
  - остальные четыре: `map_Kd immersivegeology:block/multiblock/<mb>/default` — без `.png`,
    без слэшей Windows.

### 3.4 Развёртка и flip_v

- Одна atlas-развёртка на машину, острова с полями 2–4 px (на 256×256), важные грани
  (front, панели, барабан) крупнее, второстепенные мельче; острова по возможности
  осевыровнены — так текстура читается в стиле мода.
- UV строго в диапазоне 0..1 (проверяет `check_model.py`).
- Все сгенерированные модели мода имеют `flip_v: true`. Из Blender экспортируйте **без**
  галочки flip V — тогда картина в UV-редакторе Blender над вашей PNG совпадёт с тем, что
  увидит игра. Для моделей из других редакторов: запеките тестовую текстуру с асимметричной
  надписью, поставьте машину в игру; если надпись зеркальна по вертикали — инвертируйте V
  у развёртки (или всю PNG, но тогда и `default_active` тоже).
- Шаблон развёртки для рисования: `python3 tools/tpp/uv_template.py <mb> --size 1024`
  (или `--overlay`, чтобы положить сетку островов поверх текущей `default.png`);
  результат в `docs/art/uv/<mb>_uv.png`: зелёные контуры = где какая грань лежит на атласе,
  ось V нарисована так, как её видит игра/Blender.

### 3.5 Самопроверка перед коммитом

```bash
python3 tools/tpp/check_model.py <mb>      # bbox, материалы, MTL-пути, vt 0..1, текстуры на диске, split-json
python3 tools/tpp/check_model.py --all
```

Скрипт ругается (exit 1), если модель вылезает за bbox структуры (split-рендер теряет такие
грани), если имя материала не совпадает с контрактом датагена, если в MTL абсолютный путь
или если текстура не лежит рядом. Предупреждает при >6 тыс. треугольников.

## 4. Текстуры

### 4.1 Формат и палитра

- PNG, 8 бит, RGBA; 256×256 (минимум 128×128). Непрозрачные области — alpha 255;
  дырки (решётки, жалюзи) — alpha 0, но см. §4.3 про render type.
- Палитра-якорь (§1.1): сталь `#5c5c5c`/`#414141`, швы `#1a1a1a`, ржавчина `#7b5b43`/`#5d493b`,
  бетон `#8a8a86` с потёками, шамот `#6e665c`/`#786e64`; сигнальные акценты: красные
  вентили/маховики `#a03020`, жёлтые ограждения `#c8a020` (как на фото градирен).
- Пиксельная плотность: лицевые грани и панели ≈16 px на блок, второстепенные ≈8 px на блок
  (на атласе 256 для машины 5×7×5 этого хватает).
- Без сглаживания и градиентов «фото-стиля»: стиль мода — жёсткий пиксель, шум металла
  точками/штрихами, тени запечённые в текстуру (AO по кромкам).

### 4.2 Активное состояние (`coal_boiler`)

`default_active.png` — **полная копия** `default.png` (тот же OBJ, те же UV), в которой
перекрашены только зоны свечения: гляделки горелок и окно топки. Ориентиры по моду:
янтарь `#ffa100/#ffbf00/#805e2b` (bulk_blast_furnace) или угольно-оранжевый
`#ff5500/#ff6600/#aa5500` (reverberation_furnace); доля изменённых пикселей 0,2–5 %.
Ничего другого в active-копии не двигать: смещённый на пиксель остров = «плывущее» свечение.

### 4.3 Прозрачность и render type

Если в текстуре есть alpha=0 (жалюзи градирни, решётки, просветы), блоку машины нужен
cutout-слой, иначе прозрачные пиксели отрисуются чёрным/сплошным. В репозитории это
делается одной строкой в `IGClientRenderHandler.register()`:

```java
setRenderType(IGMultiblockProvider.COOLING_TOWER.block().get(), RenderTypeSkeleton.CUTOUT_MIPPED);
```

(прецеденты: `COREDRILL`, `CHEMICAL_REACTOR`, `REVERBERATION_FURNACE`, `BLOOMERY`,
`GRAVITY_SEPARATOR`, `ROTARYKILN`). Для новых машин строки **ещё не добавлены** — добавьте
сами или скажите, добавлю. Если прозрачность не используете — ничего делать не надо.

### 4.4 Анимации (опционально)

`.png.mcmeta` рядом с PNG анимирует **всю** текстуру (все кадры — фреймы), прецеденты:
`foundry/conveyor.png.mcmeta`, `block/fluid/default_still.png.mcmeta`. Для атласа целой
машины это почти всегда неприемлемо; если очень хочется мигающую топку — выносите её в
отдельный материал (как у `ballmill`: 4 материала/4 текстуры), что для `coal_boiler`
означает переход с «injected»-схемы (`#coal_boiler`) на `genericmultiblock` и ручные пути в
MTL — см. `MULTIBLOCK_MODELS.ru.md` §3.2 и §5.2.

### 4.5 Жидкости цепи — текстуры не нужны

`flue_gas` и `hot_water` рисуются стандартными текстурами мода: `IGFluidType` берёт
`block/fluid/default_still|flowing` (газ — `IS_GAS`), а цвет даёт тонировка материала
(`0xff4d4743` дымчато-бурый, `0xffc07038` янтарный). Свои still/flowing для них потребуют
правки `IGFluidType` (там выбор текстур зашит) — не арт-задача.

### 4.6 Иконка предмета

Item-модель = тот же OBJ с display-трансформами (`IGComplexItemModelProvider.generateCoalChpModel`,
масштабы в руке уже заданы: 0.0625 / 0.09375 / 0.125). Если в руке/GUI машина не читается —
сделайте упрощённый `display_<mb>.obj` (прецеденты `ballmill/display_ballmill.obj`,
`steam_turbine/steam_turbine_item.obj`) и поправьте соответствующую строку провайдера.

## 5. Экспорт и раскладка по репозиторию (пошагово)

1. Blender: модель + развёртка (§3).
2. `File > Export > Wavefront (.obj)`: apply modifiers, нормали и UV включены, материалы
   включены, Path Mode = strip/none; оси по умолчанию (Forward −Z, Up Y) — так же, как у
   всех OBJ репозитория. Рядом ляжет `.mtl`.
3. Поправьте `.mtl`: имя материала = имя машины; `map_Kd` по §3.3. Уберите суффиксы `.001`
   из `usemtl`/`newmtl`, если Blender их добавил.
4. Положите файлы поверх заглушек (имена и каталоги — из §0), ничего не переименовывая.
5. Нарисуйте/положите `default.png` (и `default_active.png` для котла) в каталог текстур.
6. `python3 tools/tpp/check_model.py <mb>` — до зелёного `OK`.
7. Пересоздайте generated-ассеты: с JDK 17 и сетью — `./gradlew runData`; без них —
   `python3 tools/tpp/datagen_mirror.py` (пишет те же JSON, что и датаген: blockstate,
   split/mirrored, item-модели, loot). Закоммитьте `src/generated/resources`.
8. В игре: соберите структуру молотом инженера; проверьте 4 поворота; у `cooling_tower` —
   mirror; у `coal_boiler` — active (топливо + вода + редстоун); предмет в руке и в GUI;
   партиклы при разрушении; `F3+T` после правок текстур.
9. Коммит: арт + сгенерированные JSON одним коммитом; исходники (.blend/.psd) и мудборды в
   репозиторий **не** кладутся.

## 6. Чек-лист приёмки

- [ ] `check_model.py <mb>` → OK (bbox, материалы, MTL, vt, текстуры).
- [ ] `runData`/`datagen_mirror` перегенерированы, дифф generated чистый и осмысленный.
- [ ] В игре: формирование, 4 поворота, mirror (градирня), active (котёл).
- [ ] Нет чёрных квадратов (alpha без cutout), нет z-fighting, нет «плывущего» свечения.
- [ ] Развёртка не вылезает за 0..1, острова не перекрываются между собой.
- [ ] Предмет читается в GUI и в руке (или сделан `display_<mb>.obj`).
- [ ] Веса: OBJ ≲ 200 КБ, PNG ≲ 100 КБ на машину.
- [ ] Стиль сверен с §1.1 (палитра/шум/шов), силуэт — с раскладкой блоков (§1.3, §2).

## 7. Опциональные расширения (требуют кода, не только арта)

| Хочу | Что потребуется |
|---|---|
| Скины окраски (как `steam_turbine`: green/industrial/steampunk) | enum по образцу `IGSteamTurbineSkins` (+ `IIGMultiSkinHelper`, `IMultiSkinBlock`), регистрация машины skinnable-вариантом в `IGMultiblockProvider`, датаген-вызов `generateMultiskinMultiblock(...)`, текстуры `<skin>.png` (+`<skin>_active.png`), предмет скина `<mb>_multiblock_skin_<name>` |
| Несколько материалов/текстур на машину (как `ballmill`: axle/gear/drum/base) | перевод датагена машины на `genericmultiblock(...)` и ручные пути в MTL на каждую текстуру |
| Свои текстуры жидкостей | правка `IGFluidType` (сейчас выбор still/flowing зашит: default/molten) |
| Прозрачность в атласе | строка `setRenderType(..., CUTOUT_MIPPED)` в `IGClientRenderHandler.register()` (§4.3) |
| Анимированные узлы | отдельный материал + `.mcmeta` (§4.4) |
